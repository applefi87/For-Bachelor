## 0. 關鍵決定（一頁版）

1. **三種聲音、三種字**：海裡的系統字用黑體（Noto Sans TC），紙上的系統字用明體（Cactus Classical Serif），**只有使用者自己打的句子**用手寫體（芫荽 Iansui）。數字與編號用 IBM Plex Mono；真的學名才用 EB Garamond 斜體。Cormorant Garamond 整個拿掉。
2. **手寫體從霞鶩文楷換成芫荽**：我把兩套 Google Fonts 檔案實際排出來比對，**霞鶩文楷 TC 用的是傳承字形**（為→爲、真→眞、青→靑、值→値）。這裡寫的是使用者自己的句子，應該是他在學校學的字形。芫荽同樣衍生自 Klee One，風格幾乎一樣，但字形依台灣教育部標準。詳見 1.2。
3. **明體只出現在紙上（淺底），黑體只出現在海裡（深底）**。現在「字太細」是因為筆畫細的文楷被放在深色底的 12～13px；明體的細襯線也有同樣的問題，所以不進深色底。
4. **只留 6 級字**：28／20／17／15／13／12（桌面只有前兩級放大到 36／22）。**中文一律不加字距**，現在的 11 種字距全部刪掉。中文最小 13px，12px 只給等寬數字。
5. **首屏字型從約 1.1 MB 降到約 0.5 MB**：現在首屏同時載入霞鶩文楷 400 和 700（兩套靜態檔，約 528 KB＋540 KB）；新方案首屏只載入 Noto Sans TC（可變字型，400 和 500 共用同一組檔案，約 515 KB）。明體和手寫體要等打開紙、或使用者開始打字時才下載。
6. **文案**：238 條逐條重寫，這些字串的漢字從 3,908 字減到 1,698 字（−57%）。主要流程每個畫面讀到的字減少 39%～63%（多數在 45%～55%），海的來信減少 80% 以上。整個字串庫只減少 21%，因為裡面有 60 個情緒字、名字、小知識、陪法的問題這些不該刪的內容；加上 2.6 節的區塊刪減後約 −27%。
7. **禁用**：沒關係、慢慢、輕輕、一下下、好好、辛苦了、就好／就夠了、驚嘆號、日文中點「・」、「— 海」簽名，以及「不是……是……」「……也是一種……」「值得被……」「你可以……（給許可）」這幾種句型。
8. **同一個詞只指一件事**：「心情」只指儀式；每日來信選的叫「天氣」；水母名片上的量表叫「開心」。

**每個選擇的理由**

- **介面黑體：Noto Sans TC 400／500。** 台灣標準字形；在 Google 上是可變字型，400 和 500 用同一組檔案，多一個字重不用多花流量；12～15px 深色底上的筆畫最穩。Chiron Hei HK 有 17 MB 而且是香港字形，排除。**不用 700**：深色底上 700 會糊，500 就夠拉開層級。
- **紙上明體：Cactus Classical Serif 400。** 選它而不是 Noto Serif TC 有三個理由：(1) 它的字形和筆畫是舊式鉛字的樣子，正好是海克爾圖版、博物誌的年代感，Noto Serif TC 則是現代的預設明體，正是「看起來像 AI 做的」那一類；(2) 檔案大約只有 Noto Serif TC 的一半（399 KB 對 774 KB）；(3) 只有一個字重，紙上的層級只能靠字級、顏色和細線，這本來就是圖版的做法。
  - **要老實說明的代價**：它用傳承字形（為→爲、真→眞、青→靑、值→値）。台灣讀者讀舊書都看得懂，放在「舊圖版」的脈絡裡是加分，但**要先給使用者看這四個字確認**。如果他不接受，就換成 Noto Serif TC 400（其他規則都不用改，只是紙上每次多載約 1.9 倍）。
  - 小於 15px 的紙上文字（欄位名、註記）用黑體 13px，因為 Cactus 在 12～13px 的襯線會斷。
- **手寫：芫荽 Iansui 400（取代霞鶩文楷）。** 霞鶩文楷的風格本身合適（楷書、像用筆寫的、不可愛），但：(1) TC 版是傳承字形，寫的卻是使用者自己的話；(2) 它是靜態字型，現在載入 400 和 700 兩套，首屏就多了約 540 KB；(3) 在 12～13px、深色底上太細。芫荽和霞鶩文楷都衍生自 Klee One（依兩個專案的說明；我只在排版上確認過兩者筆形幾乎相同，沒有逐字比對），而且芫荽依台灣標準字形。**只用 400，不准粗體**；手寫字最小 17px；主要出現在淺色紙上（藍黑墨水色 `#23466b` 對 `#efe8d8`，對比 7.97:1），在深色的儀式輸入框裡用 17px 的 `#e8f4f6`。
- **數字：IBM Plex Mono 400。** 老實說明：我量過，Noto Sans TC、Cactus、芫荽、霞鶩文楷的數字**本來就是等寬的**（`1111` 和 `8888` 同寬，開不開 `tabular-nums` 都一樣），所以等寬字不是為了對齊，而是為了一種**聲音**：「這是量出來的數字、這是編號」。只用 latin 那一片，約 14 KB。只用 400。
- **學名：EB Garamond Italic 400。** 只用在圖版上的學名，以及說明牌上物種名後面的學名；約 25 KB。真正的學名本來就要用斜體，所以它有資訊。**「Moon Jelly Aquarium」這種英文副標全部刪掉**。
- **刪掉 Cormorant Garamond**：它現在用在強度數字、呼吸秒數、晚安時鐘、專線號碼、簽名，也就是審查圖第 13 處「突然換字體」。

**家族數**：中文 3 個（上限）＋拉丁 2 個。拉丁兩個加起來約 40 KB，比一片中文切片還小。如果一定要壓到 4 個家族，就把 EB Garamond 拿掉，學名改用正體的 Plex Mono（缺點是像程式碼，不像圖版）。

### 1.3 載入方式（給工程）

```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Noto+Sans+TC:wght@400;500&family=Cactus+Classical+Serif&family=Iansui&family=IBM+Plex+Mono&family=EB+Garamond:ital@1&display=swap">
```

```css
:root {
  --f-sans:  "Noto Sans TC", "PingFang TC", "Microsoft JhengHei", system-ui, sans-serif;
  --f-serif: "Cactus Classical Serif", "Noto Serif CJK TC", "Songti TC", "PMingLiU", serif;
  --f-hand:  "Iansui", "Kaiti TC", "BiauKai", "DFKai-SB", serif;
  --f-mono:  "IBM Plex Mono", ui-monospace, "SF Mono", Menlo, Consolas, monospace;
  --f-latin: "EB Garamond", "Iowan Old Style", Georgia, serif;   /* 只配 font-style: italic */
  font-synthesis: none;   /* Cactus 和芫荽都只有 400：禁止瀏覽器假造粗體、斜體 */
}
body { font-family: var(--f-sans); }
.paper { font-family: var(--f-serif); }
.hand, .field, textarea { font-family: var(--f-hand); font-weight: 400; }
```

- 一個 `<link>` 就好。Google 的 CSS 很小，真正的下載是依 `unicode-range` 按需發生的。
- **不要 preload 任何中文切片**（猜不準要哪一片，會浪費流量）。
- 進到主畫面、閒下來之後（`requestIdleCallback`），可以用 `document.fonts.load('17px "Cactus Classical Serif"', '圖鑑本週紀錄潮汐來信的了是在有')` 先暖紙上最常用的幾片，第一次打開圖鑑時比較不會閃一下。
- **危機元件不要等網路字型**：用 `font-family: system-ui, -apple-system, "PingFang TC", "Microsoft JhengHei", sans-serif`，讓它一出現就是最終樣子，不會重排。這和另一條工作線「全站唯一不套美術風格的安全元件」的方向一致。
- `<b>`、`<strong>`、`h1–h3` 的預設粗體要在 CSS 重設成 500（黑體）或 400（明體、手寫），不然 `font-synthesis: none` 之後，明體標題會退回系統字的粗體。

### 1.4 字級尺度（6 級）

| 級 | 名稱 | 手機 390 | 桌面 ≥ 768 | 行高 | 字重 | 字距 | 用在 |
|---|---|---|---|---|---|---|---|

- **中文最小 13px**。12px 只給等寬數字和拉丁字母。
- **輸入框至少 16px**（iOS Safari 對小於 16px 的輸入框會在聚焦時自動放大畫面），所以全部用 L3 17px。
- 行高：中文閱讀需要比拉丁字大的行距，紙上內文用 1.75；介面 1.6；標題 1.4；只有 L1 用 1.2。
- **字重只有 400 和 500**。黑體 500 用在標題與按鈕，其餘 400。明體、手寫永遠 400。

**字距規則**：中文字身框本來就包含字與字之間的空間，再加字距會讓句子散掉、標點後面出現大洞，置中時最後一個字的右邊還會多出一格（現在入口大標是用 `padding-left: 0.32em` 硬補回去的）。所以：

1. 中文 `letter-spacing: 0`，**沒有例外**，包括兩個字的按鈕和標題。
2. 只有全大寫的拉丁縮寫（No.、PL.）可以加 0.04em。
3. 刪掉現在的 11 種字距：0.32em（入口大標）、0.22em（HUD 館名）、0.2em（呼吸字）、0.18em（入口副標）、0.14em（英文 kicker）、0.12em（sub-h）、0.1em（附註、fact）、0.08em（星星、大按鈕、名字）、0.06em（抽屜標題、modal 標題、專線號碼、英文 logo）、0.05em（.mono）、0.04em（儀式標題）。

## 2. 文案

### 2.1 現況

只算使用者看得到的字串（去掉註解）：「慢慢」23、「不用」21、「沒關係」9、「就好／就夠」12、「輕輕」5、「一下下」6、「好好」5、「辛苦」3、「溫柔」8、「也可以」10、「・」39、「……」8、「！」6。簡報寫的 26／21／10 是包含註解的數字。

問題不只是用詞，而是**每一句都在做同一件事：安慰**。儀式的說明在安慰、結果卡在安慰、歡迎回來在安慰、商店的錯誤訊息（「再等一下下」）也在安慰。當每一句都是同一種溫度，句子就沒有重量，而且會變成在告訴使用者「你應該有什麼感覺」。

### 2.2 四種聲音

**A. 海裡的展示牌**（HUD、下方選單、生物旁的說明牌、通知、提示、儀式）
- 寫事實：先寫物件，再寫狀態。名詞加數字。
- 能寫成欄位就寫成欄位：「欄位名（2 字）＋全形空格＋值」。
- 通知：主句 ≤ 12 字；需要時加第二行。
- 不評價使用者、不給許可、不預測他的感受。
- 例：「牠背著『另一邊之殼』，在沙地上慢慢走。」→「背著　另一邊之殼」

**B. 紙上的紀錄**（圖鑑、名冊、潮汐圖、本週紀錄、珍珠盒、每一筆心情的紀錄卡）
- 像觀察筆記：日期開頭；第三人稱寫生物；寫「你」的時候只陳述他做了什麼，不下結論（不寫「你做得很好」「進步了」）。
- 可以寫完整句子，但一句一個事實。
- 真實世界的資料和這座館的規則分開放：欄位「實際生態」「在這座館裡」。
- 空狀態寫「此頁空白。」
- 例：「這一週，你替 12 份感覺取了名字。」→「共 12 筆。」

**C. 海的來信**
- 一封最多三塊：今天的天氣（一句，寫這片海今天的樣子）＋本文（一句海的事實或畫面）＋附記（小知識）。
- 可以有溫度，但**溫度要來自具體的畫面和事實**，不是來自形容使用者或給建議。
- 不用命令句，不把「你」當成被評價的對象，不署名；頁尾是日期和第幾封。
- 例：「浪會退，也會再來。你也是。」→「浪會退，也會再來。」（道理讓讀的人自己想到，或者不想到。）

**D. 系統操作**（按鈕、確認框、錯誤、空狀態、設定）
- 按鈕用動詞（加受詞），2～5 字。**同一個動作全站同一個詞**：關閉＝「好」、取消＝「取消」、接受禮物＝「收下」、回上一頁＝「返回」。
- 確認框：標題是問句（「要○○嗎？」），內文一句後果。
- 錯誤：發生了什麼＋差多少或怎麼辦（「光不夠，還差 40」），不道歉、不安撫。
- 提示：「動作：結果」（「點水面：撒下浮游生物」）。
- 抽屜標題＝打開它的按鈕名（「商店」而不是「貝殼商店」）。
- **危機元件是唯一例外**：它的工作是把打電話的門檻拿掉，所以可以用「不用想好要說什麼」這種句子；不套館內的語氣和字型。

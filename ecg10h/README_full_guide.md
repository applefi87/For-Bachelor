# Part 1｜為什麼是這個實驗

「為什麼做這個」有三個互不相同的答案，取決於你站在哪個位置問。分開講比較清楚。

---

## 1A. 從「研究」的角度

### 這條 pipeline 是生醫訊號研究的標準骨架

打開任何一篇生理訊號的論文，結構幾乎都是同一個形狀：

```
原始訊號 → 前處理 → 特徵／表徵 → 模型 → 驗證 → 詮釋
```

你要跑的四支腳本，就是把這個骨架完整走一遍。學會這條骨架之後，你讀論文的方式會改變——你會知道每一節在幹什麼、以及作者在哪一節偷懶了。

這是這個實驗**唯一的研究價值**：它讓你看懂研究的形狀。

### 但要誠實：它沒有研究新穎性

用 HRV 和熵指標分類心電圖，是 1990 年代就在做的事。你不會發現任何新東西，也不該假裝會。

**它是複製，不是創造。** 而複製一次既有做法，正是所有研究訓練的第一步——你得先能重現別人做過的，才有資格談做新的。

### 為什麼選 PTB-XL 而不是別的資料

| 條件 | PTB-XL 的狀況 |
|---|---|
| 免費、免申請 | ✓ 直接下載，不用倫理審查 |
| 有專家標註 | ✓ 21,799 筆，兩位心臟科醫師標註 |
| 規模夠但不失控 | ✓ 100Hz 版本約 1.7GB，可串流 |
| 有 benchmark 論文 | ✓ 你的結果有得比對，知道自己做得好不好 |
| 有官方的分割方式 | ✓ `strat_fold` 欄位，避免資料洩漏 |

最後一項最重要，多數玩具資料集沒有。

### 這個實驗真正在教的三件事

**第一，特徵是一種假設。** 你選 HRV 和熵，等於在假設「心肌梗塞會改變心律的規律性」。這個假設部分正確、但不完整——MI 的主要特徵在 ST 段和 Q 波的**形態**上，不在心律。所以你會得到一個「有效但不夠好」的結果。**理解為什麼不夠好，比得到好結果更有價值。**

**第二，驗證比結果重要。** 負對照（打亂標籤重跑）是把「玩票」和「研究」分開的那條線。沒有負對照的漂亮數字，一文不值。

**第三，降維圖不能拿來當證據。** UMAP 一定會畫出看起來有分群的圖，即使資料裡完全沒有結構。這是它的數學性質，不是你的發現。所以要配 silhouette score 和負對照。

## 1B. 從「申請研究所」的角度

這裡的評分邏輯**完全不同**。

### 委員不在乎你的 AUC

真的不在乎。你的數字是 0.68 還是 0.82，對錄取與否毫無影響。他們在乎三件事：

1. **這個人開始了嗎？** — 讀書計畫裡「我打算學 AI」和「我已經在做了」是天差地別的兩句話
2. **他能不能講清楚自己做了什麼？** — 講不清楚 = 沒真的做
3. **他知道自己不知道什麼嗎？** — 這是研究生和學生的分野

### 具體對應到你的申請文件

你的讀書計畫 C-1 現在寫著：

> 我正以 PhysioNet 公開的 PTB-XL 心電圖資料集進行實作練習，內容包括生理訊號的讀取與前處理、特徵萃取、分類模型訓練與評估，以及降維後的結構視覺化。

**跑完這個實驗，這句話從「計畫」變成「事實」。** 這是它對申請最直接的作用。

### 面試時你可以講的三件事

跑完之後，你手上會有三個很強的談話素材：

**第一個（最強）：資料洩漏那件事**

> 「我一開始用隨機交叉驗證，後來發現 PTB-XL 同一個病人可能有多筆紀錄，隨機分折會讓模型認得病人而不是認得病。所以改用資料集本身提供的 strat_fold 分組。修正後 AUC 掉了多少，那個差距就是洩漏的量。」

這段話會讓委員知道你不只會跑套件，你知道結果什麼時候不能信。**這是研究生的門檻。**

**第二個：為什麼結果不夠好**

> 「我的 AUC 只有 0.7 左右。原因是我只用了單一導程的心律變異度和熵指標，而心肌梗塞的診斷特徵主要在 ST 段和 Q 波的形態上。要提升就得加入形態特徵，或改用能學形態的模型。」

**「我做了，結果不好，而且我知道為什麼」比「我做了，AUC 0.95」有說服力得多。** 後者通常代表有洩漏或過擬合，而且答不出追問。

**第三個：你想改什麼**

如果你在跑完之後真的改了幾個參數、換了幾組特徵，那就有第三個素材：你不只執行，你在探索。

### 對「大學肄業」的側面作用

這一點值得單獨講。

你的學歷有缺口，這是事實。而彌補學歷缺口最有效的東西，不是解釋，是**近期的、可驗證的、有紀錄的產出**。

一個橫跨幾週、有 commit 紀錄、有輸出檔案、有技術筆記的專案，說的是「這個人現在的狀態是這樣」。委員看的是現在的你，不是十年前那個沒畢業的你。

## 02_first_ecg.py — 讀一筆、畫出來

### 在幹什麼
讀一筆 12 導程心電圖，畫全貌圖，再對 Lead II 做濾波和 R 波偵測。

### 技術點：12 導程是什麼

心電圖用 10 個電極產生 12 個「視角」（I, II, III, aVR, aVL, aVF, V1–V6）。每個導程是從不同角度看心臟的電活動。

**為什麼腳本挑 Lead II**：它的 R 波最明顯，臨床上看心律最常用。做心律分析時單看它就夠；但**做形態診斷（例如 MI 定位）就必須看多導程**——這也是你的 AUC 上不去的原因之一。

### 技術點：`ecg_clean()` 做了什麼

不是黑盒子，它做兩件事：

1. **高通濾波**（約 0.5 Hz）去掉基線漂移——呼吸和電極移動造成的緩慢起伏
2. **低通／notch** 去掉高頻雜訊和 50/60 Hz 市電干擾

### 技術點：R 波偵測

`ecg_peaks()` 預設用 NeuroKit 改良的 Pan-Tompkins 演算法：微分 → 平方 → 移動積分 → 自適應閾值。

**要驗證它做對了**：看 `first_ecg_peaks.png`，紅色三角形應該都落在尖峰上。**偵測錯了，後面所有 HRV 特徵都是垃圾。** 這一步一定要用眼睛確認。

## 03_features.py — 抽特徵

### 在幹什麼
選出 NORM 和 MI 各 150 筆，逐筆串流讀取，算出一組數字，存成 CSV。

### 技術點：SCP codes 與診斷分類

PTB-XL 的標註用 SCP-ECG 代碼（例如 `IMI` = 下壁心肌梗塞）。`scp_statements.csv` 把這些代碼對應到五個診斷大類：

| 代碼 | 意義 |
|---|---|
| NORM | 正常 |
| MI | 心肌梗塞 |
| STTC | ST/T 波改變 |
| CD | 傳導障礙 |
| HYP | 心室肥大 |

**腳本只挑「單純只有一個大類」的紀錄**（`db.dx == {"NORM"}`）。因為很多病人同時有多種問題，混進來會讓「兩類」的界線模糊，結果變得無法解讀。

想換題目就改這兩行，例如 `db.dx == {"STTC"}`。

### 技術點：HRV 特徵各是什麼

| 特徵 | 意義 |
|---|---|
| `HRV_MeanNN` | 平均心跳間隔（毫秒）——基本上就是心率的倒數 |
| `HRV_SDNN` | 間隔的標準差——整體變異程度 |
| `HRV_RMSSD` | 相鄰間隔差值的均方根——**反映副交感神經活性**，短時間紀錄的主力指標 |
| `HRV_pNN50` | 相鄰間隔差 > 50ms 的比例 |
| `HRV_CVNN` | SDNN / MeanNN，標準化後的變異 |

### 技術點：熵特徵各測什麼

這幾個是「複雜度」指標，測的是訊號的**不可預測性**：

| 特徵 | 測什麼 | 白話 |
|---|---|---|
| `samp_ent`（樣本熵） | 短片段重複出現的機率 | 這段訊號有多「自我相似」 |
| `perm_ent`（排列熵） | 相鄰數值大小順序的分佈 | 起伏模式有多雜亂 |
| `spec_ent`（頻譜熵） | 頻譜能量的分散程度 | 能量集中在少數頻率，還是攤平 |
| `hjorth_mob/comp` | 一階、二階導數的統計 | 訊號變化的快慢與複雜度 |

**為什麼放這些**：這是羅孟宗老師方法論的入門版。生理訊號的健康與否，常常反映在「複雜度」而不是「平均值」上——太規律和太混亂都可能是病態。

### 技術點：續跑機制

腳本每 10 筆存一次 CSV，重跑時會跳過已完成的。網路斷了不用重來。

### 注意
- `N_PER_CLASS = 150` 想快就改小。50 筆也能跑完整流程
- 用 Excel 打開 `features.csv` 看一眼。**每一列是一個病人，每一欄是一個數字**——這一步的全部意義就是把訊號變成表格

## 04_model_3d.py — 模型 + 驗證 + 3D 圖

### 在幹什麼
訓練分類器、做負對照、看哪些特徵有用、降到 3 維畫互動圖。

### 技術點：為什麼看 AUC 不看 accuracy

Accuracy 在類別不平衡時會騙人。假設 90% 是正常，模型全猜「正常」就有 90% accuracy，但它什麼都沒學到。

**AUC（ROC 曲線下面積）**衡量的是「模型把正例排在負例前面的能力」，不受類別比例影響。0.5 = 隨機，1.0 = 完美。

### 技術點：負對照的原理

把標籤隨機打亂，重新訓練。此時特徵和標籤之間**理論上沒有任何關係**，所以 AUC 應該是 0.5。

如果打亂後還是很高 → 你的流程有洩漏或 bug。
如果真標籤明顯高於打亂 → 訊號是真的。

**這一步花不到一分鐘，但它是整個實驗最重要的一行程式。**

### 技術點：UMAP vs PCA vs t-SNE

| 方法 | 特性 | 什麼時候用 |
|---|---|---|
| PCA | 線性、可解釋、保留全域方差 | 想知道「哪幾個方向變化最大」 |
| t-SNE | 非線性、保留局部鄰近、**全域距離無意義** | 看局部群集 |
| UMAP | 非線性、局部+部分全域、比 t-SNE 快 | 一般首選 |

**最重要的警告**：UMAP 的圖上，**群集之間的距離沒有意義**，群集的大小也沒有意義。你只能說「這些點彼此接近」，不能說「A 群比 B 群遠所以更不同」。

很多人拿 UMAP 圖下結論，那是錯的。所以腳本才加了 silhouette score。

### 技術點：silhouette score

量化「同類的點是否比異類的點更靠近」。範圍 -1 到 1，越高越好。

腳本同時算真標籤和打亂標籤的 silhouette。**兩個數字的差距才是證據，單看圖不是。**

### 技術點：feature importance 的陷阱

隨機森林的 feature importance 對**高基數、連續型**的特徵有偏好，而且相關特徵之間會互相稀釋重要性。

所以「MeanNN 最重要」這個結論要謹慎——它可能只是因為 MeanNN 的數值範圍大。想嚴謹一點要用 permutation importance。

**這個陷阱可以寫進你的技術報告的「限制」章節。有「限制」章節的報告，比沒有的可信十倍。**

## 05_fix_data_leakage.py — 必跑

### 為什麼有這一支

我在寫 04 的時候用了 `cross_val_score` 的預設隨機分折。這在 PTB-XL 上是**錯的**，因為同一個病人可能有多筆紀錄——隨機分折會讓同一個人的資料同時出現在訓練集和測試集。

模型於是學會「認得這個人」，而不是「認得這個病」。AUC 虛高，而且你不會察覺。

### 修正方式

PTB-XL 的 metadata 有 `strat_fold` 欄位（1–10），官方已經保證同一病人的所有紀錄都落在同一折。用它分折就安全。

腳本同時把補值（imputer）包進 sklearn 的 `Pipeline`，確保中位數只從訓練集算——這是另一個常被忽略的細微洩漏。

### 這一支的價值

**它是整包腳本裡對你最有用的一支**，因為：

1. 它讓你的結果從「可能是假的」變成「站得住」
2. 它給你面試時最好的一段話
3. 它示範了研究裡最重要的習慣：**懷疑自己的好結果**

跑完之後，記下 04 和 05 的 AUC 差多少。那個差距就是洩漏的量，是你自己量出來的。

# Part 4｜需要注意的陷阱

依重要性排序。前三個會實質影響結論。

### 1. 資料洩漏（最嚴重）
同一病人跨折。**用 05 那支解決。** 這是口試委員第一個會問的。

### 2. 沒有負對照
沒有負對照的結果不能信。已經寫進腳本，不要跳過。

### 3. 補值造成的洩漏
用全部資料的中位數補 NaN → 測試集的資訊滲進訓練。05 的 Pipeline 已處理。

### 4. 只跑一次就下結論
`random_state=0` 固定住了隨機性，方便重現，但單次結果有運氣成分。想嚴謹就換幾個 seed 多跑幾次，看結果穩不穩。

### 5. 100Hz 對 MI 可能不夠
PTB-XL 有 100Hz 和 500Hz 兩版。腳本用 100Hz（`filename_lr`）省時間，但 ST 段和 Q 波的細節在 100Hz 下可能被抹掉。這是你 AUC 上不去的原因之一，**值得在報告裡誠實寫出來**。

### 6. R 波偵測失敗
訊號品質差時偵測會出錯，HRV 特徵就全錯。腳本記錄了 `n_beats`，**檢查一下有沒有異常值**（10 秒的紀錄應該有 8–20 個心跳，出現 2 或 50 就是偵測爆了）。

### 7. 類別選擇造成的樂觀偏誤
腳本只挑「單純只有一個診斷」的紀錄，這讓兩類比實際情況更好分。真實臨床上病人是混合的。**這是刻意的簡化，但要寫出來。**

### 8. UMAP 圖的過度詮釋
已在上面說明。**圖好看不等於有結構。**
